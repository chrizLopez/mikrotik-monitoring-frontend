# MikroTik Monitoring Frontend

React 19 + Vite frontend for a local MikroTik mini-ISP monitoring system backed by a Laravel API.

## Stack

- React 19
- Vite
- TypeScript
- React Router
- Tailwind CSS
- TanStack Query
- Axios
- Recharts
- Vitest + Testing Library

## Environment

Create a `.env` file in `Frontend/`:

```env
VITE_API_BASE_URL=http://localhost:8000
```

## Install

```bash
npm install
```

## Run

```bash
npm run dev
```

## Build

```bash
npm run build
```

The production build also generates the PWA service worker and precache manifest.

## Test

```bash
npm run test
```

## App Routes

- `/login`
- `/`
- `/isps/:ispId`
- `/users`
- `/users/:userId`
- `/status`

## Project Structure

```text
src/
  app/               providers
  components/        shared UI building blocks
  features/
    auth/            login + session state
    dashboard/       overview page + summary queries
    isps/            ISP detail query/page
    status/          status page
    users/           user reporting + detail pages
  lib/               axios, query client, formatting helpers
  routes/            router definition
  test/              shared test setup
  types/             API contracts
```

## Notes

- Authentication expects Laravel session endpoints at `/api/login`, `/api/logout`, and `/api/me`.
- Axios is configured with `withCredentials: true` for cookie-based auth.
- The frontend assumes normalized backend values and keeps business logic focused on presentation, filtering, and chart UX.
- The UI reflects the shared 3-WAN PCC model: Gomo, Starlink ISP New, and Smart Bro ISP.
- Group A and Group B remain reporting labels only and do not imply WAN assignment.
- `GROUP_A_TOTAL` should not appear in monitored user rows.

## PWA

- Manifest: `public/site.webmanifest`
- Icons: `public/icons/`
- Service worker: generated by `vite-plugin-pwa` during `npm run build`
- Registration: `src/features/pwa/register-service-worker.ts`

### Installability Behavior

- Static frontend assets are precached so the app shell can reopen offline after the first successful load.
- Navigation requests use a conservative network-first strategy with cached shell fallback.
- Requests matching `/api/` are `NetworkOnly`, so live monitoring data is never served from the service worker cache.
- The UI shows an install action when `beforeinstallprompt` is available and shows iPhone/iPad instructions when Safari requires manual home-screen installation.
- When offline, the app shows a banner that live router data is unavailable until the connection returns.

### Local Testing

1. Install dependencies with `npm install`.
2. Build the production bundle with `npm run build`.
3. Preview the production build with `npm run preview`.
4. Open the preview URL in Chrome or Edge and verify the manifest, service worker, and install prompt in DevTools Application tabs.

`vite dev` does not provide the production precache behavior, so installability checks should be done against `build` + `preview`.

### Android Chrome

1. Deploy or preview the app over HTTPS.
2. Open the dashboard in Chrome on Android.
3. Wait for the page to settle, then use the install button in the dashboard or Chrome's browser install prompt.
4. Confirm it opens in standalone mode after installation.

### iPhone / iPad Safari

1. Open the dashboard in Safari.
2. Use the Share menu.
3. Choose `Add to Home Screen`.
4. Launch the saved shortcut from the home screen to run it as a standalone web app.

### Updating Icons or Manifest

- Replace the files in `public/icons/` with branded artwork while keeping the same sizes and filenames.
- Update app metadata in `public/site.webmanifest`.
- Regenerate the placeholder PNG set with `npm run generate:pwa-icons` if needed.
- Rebuild with `npm run build` so the new assets are included in the precache list.
